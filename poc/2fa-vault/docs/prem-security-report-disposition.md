# Prem report disposition against the current tree

This document maps every finding in
`prem-security-report-run_589529df09bd4b87bb847c817c9e3dfc (1).md`
(which analyzed stale commit `61a3ca1`) to the current working tree. “Fixed”
means an adversarial regression now pins the invariant. “Out of vault scope”
means the finding concerns the generic inbound Emulator/Ark VTXO service,
which is not present in the Mutinynet two-service deployment. That generic
surface is distinct from the authorizer's narrow outbound HTTPS client to the
release-pinned public Arkade cosigner; the entries below keep that distinction
explicit rather than treating generic findings as vault fixes.

The Mutinynet boundary is browser → method-allowlisted gateway →
internal-only `cmd/authorizer`. Only the authorizer owns the private Provider
key and authoritative SQLite file. It exposes no inbound Emulator, generic
`RemoteSigner`, raw-transaction signer, demo, or caller-supplied broadcast
route. After policy approval and a durable private-signature stage, it makes
one outbound, response-reconciled call to the code-pinned public Arkade
Emulator for the third 3-of-3 signature.

## Residual release limits

- This is Mutinynet-only software isolation, not an HSM/enclave. Host/root
  compromise can read or invoke the provider key.
- The gateway-served first-party JavaScript is trusted. A compromised gateway
  can read unlocked browser secrets; the planned independently distributed
  wallet Vault mode is the next boundary improvement.
- Database HMAC detects DB-only mutation, not rollback. Restoring an old SQLite
  snapshot can roll back allowance/reservation state and requires chain/audit
  reconciliation before restart.
- Backup-key generation, secure storage, proof of possession, and signing
  remain outside this POC; only a real independent compressed public key is
  required.
- The legacy generic Emulator is a regtest development service with
  unauthenticated inbound signing APIs. It must not be substituted for,
  exposed by, or routed through the Mutinynet authorizer. The authorizer's
  separate code-pinned outbound public Arkade client remains an availability
  and transaction-privacy dependency; its response is not trusted for
  correctness.
